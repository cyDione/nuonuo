# M3 实现说明：审核、记忆、Watchdog、浏览器、沙箱

## 审核层（`packages/core/src/review.ts`）

Worker 的每条 shell 命令在执行前都要过审核闸门：

1. **风险分级**：用确定性规则判断，不消耗 token。
   - `normal`：其他命令。
   - `external`：推送、发布、发评论、向外发送数据、远程连接、发邮件。
   - `destructive`：强制推送、合并 PR、删除仓库或分支、`rm -rf` 工作目录以外的路径、删库、磁盘级操作。
2. **正则名单**：设置 → 规则与审核。「直接拦截」名单优先于「直接放行」名单，命中即处理，不调用模型。
3. **审核阈值**：低于阈值的命令直接放行，并记录审计。
4. **高风险操作默认一律交给你**（`destructive: 'ask'`），不让模型权衡。端到端测试中发现：主人在请求里明确要求强制推送时，审核模型会认为「请求已授权」而放行，违背了「一律问我」的规则。所以改为确定性地交给你。
5. **对外操作**由审核模型（`reviewer` 层，结构化输出）按你的自然语言规则判断：放行 / 拦截 / 问主人。审核模型不可用时，一律交给你。

**交给你的命令不阻塞 Worker**：工具立即返回「等待批准」，任务进入 `等你批准` 阶段，并在卡片上显示命令和原因。你批准后，命令在后台、在原工作目录、以原环境执行，结果作为 `job_finished` 送回 Worker；拒绝时会告诉 Worker 理由。任务结束时，未处理的审批自动作废。

所有决定都写进 `audit_log`（设置 → 规则与审核 → 审计记录）。

## 三层记忆（`packages/core/src/memory.ts`）

- **存储**：`memory/user.md`、`memory/agent.md`、`memory/projects/<项目>.md`，都是可以直接编辑的 Markdown。每条一行，并标注来源和日期。
- **注入提示词**：主 Agent 和 Worker 每次都带上「关于主人」和「自己的经验」两层；任务属于某个项目时，再加上该项目的记忆。项目由 `start_task(project)` 指定；GitHub 任务自动按仓库归入项目。
- **工具**：`remember` / `forget` / `search_memory`。检索用词和中文二元组的重叠打分。
- **写入约束**：同一条不重复写入；像凭据的内容直接拒绝；提示词要求只记主人说过的话和自己验证过的结论。

## Watchdog（`packages/core/src/watchdog.ts`）

- **确定性探针**：每分钟运行一次，不消耗 token。
  - 本轮超过 10 分钟没有新事件（卡住）
  - 连续 4 次相同的工具调用（循环）
  - 自上次输入后超过 60 步
  - 汇报「继续中」后 30 分钟没有动静，也没有在运行的命令
  - 后台队列连续失败、来源出错
- **去重**：同一问题在 30 分钟内只报一次。
- **处理方式**：发现问题后交给 Watchdog 模型，它会读取任务最近的执行记录，然后选择最轻的处理方式：无需处理 / `nudge_task` 提醒 Worker / `restart_task` 重启这一轮 / `notify_owner` 告诉你。它不能停止任务，也不自己干活。
- **专属对话**：你在「🛡 Watchdog」对话里写的消息直接交给它，不经过主 Agent。

## 浏览器与接管（`packages/agent-runtime/src/browser.ts`）

- **持久化配置**：使用 Playwright 加上持久化的浏览器配置目录（`browser-profile/`）。你登录一次，之后所有任务都能复用这个登录状态。每个任务有自己的标签页。
- **工具**：`browser_open / snapshot / click / type / screenshot`。快照会给页面上可见的可操作元素编号（`[e12] button "登录"`），Worker 用编号来点击或输入。
- **接管**：Worker 调用 `request_handoff`，任务卡片上出现「接管浏览器」按钮。你在网页里看到实时画面，可以点击、输入、按键、跳转地址，完成后点「交还」，Worker 被唤醒继续。远程画面的方式在没有图形界面的机器上、在手机上都能用。
- **规则**：Worker 不能自己输入密码或付款信息。
- **找浏览器的顺序**：`NUONUO_BROWSER` 环境变量 → Playwright 自带的浏览器 → 系统里的 Chrome / Chromium。

## Docker 沙箱（`packages/core/src/sandbox.ts`）

- **容器设置**：开启后，Worker 的 shell 命令在一次性容器（`--rm --init`）里运行。
  - 只挂载任务目录，挂载到相同路径。
  - 以你的 uid/gid 运行。
  - 内存上限 4g，进程数上限 512。
  - 网络可选联网或断网。
- **适用范围**：关闭 / 只对外部来源的任务 / 所有任务。
- **审核仍然生效**：审核作用于原始命令，所以开了沙箱也照常审核。

## 验证

- **单元测试**：76 个测试，包括：
  - 浏览器测试：真实启动 Chromium，覆盖打开、输入、点击、截图、接管。
  - 沙箱测试：真实启动 Docker 容器，验证只看得到工作目录、以你的 uid 写文件、断网生效。
- **端到端测试**：用真实模型（DeepSeek V4.1 Flash）跑了 6 个场景，全部通过：
  1. 强制推送被拦下，批准后执行，推送成功。
  2. 「记住…」写进了用户记忆。
  3. 浏览器遇到登录页时请求接管；在网页里的远程画面上登录后交还，Worker 读出了 3 条待办。
  4. 打开沙箱后，命令在 Debian bookworm 容器里执行。
  5. 和 Watchdog 对话。
  6. 审计记录完整。
- **已知小问题**：Worker 请求接管之后，主 Agent 偶尔会在你交还之后再转述一遍「请登录」。属于模型行为上的噪音，提示词里已经标注了「已回答，不要再转述」，但这次运行中仍然出现过一次。
